# QA TEST PLAN — CASE ZERO Vertical Slice 0.1.0 (ръчен тест на Android)

Целта е QA да провери на истинско устройство това, което автоматизираните тестове не покриват
(KNOWN_ISSUES U1–U8). Автоматизираните резултати са в `docs/TEST_REPORT.md`.

## 0. Какво се тества

| APK (в `qa/apk/`) | Package | За какво |
|---|---|---|
| `casezero-dev-0.1.0.apk` | `com.casezero.verticalslice.dev` | Пълен тест + debug overlay (бутон **DBG** горе вдясно) |
| `casezero-playtest-0.1.0.apk` | `com.casezero.verticalslice.playtest` | Тест „като играч“, без overlay; има „Export Playtest Log“ в Настройки |

Двата APK могат да са инсталирани едновременно. Release APK-то се сглобява с
`tools/build/build_android.sh release` и истински ключ; QA версиите са подписани с тестови ключове.
SHA-256 са в `qa/apk/SHA256SUMS`.

Изисквания: Android 7.0+ (minSdk 24), ARM64 устройство. Препоръчително: един малък телефон
(~360×640 dp), един голям (~412×915 dp), по възможност един с cutout и gesture навигация.

```sh
sha256sum -c qa/apk/SHA256SUMS
adb install -r qa/apk/casezero-dev-0.1.0.apk
adb install -r qa/apk/casezero-playtest-0.1.0.apk
adb logcat -s godot           # логове по време на теста
```

Чисто начало: `adb shell pm clear com.casezero.verticalslice.dev` (трие save и analytics).

## 1. Решения (за да не се блокира тестът)

**C01 „Отвореният прозорец“**
1. Tap „Отворен прозорец“ → улика „Дъжд и отворен прозорец“.
2. Tap „Под под прозореца“ → „Сух под“.
3. „Улики 2/3“ → „Направи извод“ → *Прозорецът вероятно е отворен наскоро; провери показанията.* → „Потвърди“ → „Към показанията“.
4. Tap „Карта: допълни показанията“ → „Допълнени показания“.
5. Извод 2 → *Управителят го е отворил след намирането на госта, за да проветри.* → SOLVED → Reward +100 XP.

Декор без улика: обувки, чаша, стенен часовник, покритото тяло.

**C02 „Последното обаждане“**
1. Tap „Телефон на госта“ (0%) → „Батерия при намиране“.
2. Tap „Зарядно и кабел“ → „Свържи“ (бутонът става „Свързан“).
3. Tap телефона отново → „Телефон и номер B“.
4. Tap „Проверена операторска справка“ и „Часовникът, посочен от Мира“.
5. Свързване: избери **Телефон и номер B**, **Пълна операторска справка**, **Час и статус на посочения запис** → „Свържи“.
6. Извод → *Заявеният клетъчен разговор A → B в 23:30 не се е състоял.*

**C03 „Грешният влак“**
1. Tap петте източника: билет, проверка на часовника, разписание, кадър, перон 4.
2. Timeline (от най-ранно): **R214 заминава 20:10:00** → **Начало на заявения интервал 20:15:00** → **Никола на перона 20:15:30**.
3. Свързване: **Проверено време**, **Никола на перона**, **Другият влак**.
4. Извод → *Никола не е бил в R214 през цялата минута 20:15; вижда се на перон 4.* → G_END.

## 3. Какво да се събере при бъг

* Модел на устройството, Android версия, APK (dev/playtest), стъпки, очаквано/получено, скрийншот.
* `adb logcat -s godot > bug.log`.
* Dev APK: save и analytics се взимат с
  `adb exec-out run-as com.casezero.verticalslice.dev cat files/save/save.json > save.json` и
  `adb exec-out run-as com.casezero.verticalslice.dev cat files/analytics/events.jsonl > events.jsonl`.
  Playtest APK-то не е debuggable, затова файловете му не могат да се изтеглят с `run-as`.

Не е измервано. Ако QA мери: Godot remote profiler или
`adb shell dumpsys gfxinfo com.casezero.verticalslice.dev` и
`adb shell dumpsys meminfo com.casezero.verticalslice.dev`. Бюджетите са в спецификацията, част 13.
