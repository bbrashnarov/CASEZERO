# CASE ZERO — Тест на Android телефон: инструкция стъпка по стъпка

Build: **0.1.0** (dev и playtest APK) • Време: ≈ 90–120 мин за целия тест, ≈ 15 мин за бърз тест (Част Б) • Автор: QA

Правило: **записвайте само това, което виждате.** Не маркирайте PASS, ако не сте изпълнили стъпката на телефона. Не поправяйте нищо — само докладвайте.

---

## 0. Какво ви трябва

| Какво | Подробности |
|---|---|
| Телефон | Android 7.0 или по-нов, 64-битов ARM (почти всички от последните ~8 години) |
| Втори телефон (по желание) | Един малък (~360×640 dp, малък екран) и един голям (~412×915 dp). Малкият е най-важен |
| Компютър + USB кабел | По желание. Без него тестът пак става (Път 1), но няма логове |
| Време и зареден телефон | Минимум 50% батерия |

Запишете **модела на телефона, версията на Android и размера на екрана** — те са първото нещо в доклада.

---

## 1. Подготовка на телефона (еднократно)

1. **Settings → About phone** → запишете модел и Android версия.
2. **Settings → Display → Font size** → поставете на **стандартен/по подразбиране**. (Ще го променяте по-късно.)
3. **Settings → Sound** → звукът да е включен, не е на „без звук“.
4. Изключете „Не безпокой“. Екранът да не се заключва прекалено бързо (Display → Screen timeout → 5 min).
5. Извадете SIM/уверете се, че няма входящи обаждания по време на теста.

## 2. Инсталация — изберете ЕДИН път

Двата файла са в repo-то `bbrashnarov/CASEZERO`, branch **`claude/case-zero-qa-spec-gh22bh`**, папка **`qa/apk/`**:
- `casezero-dev-0.1.0.apk` — **за пълния тест** (има бутон **DBG** горе вдясно)
- `casezero-playtest-0.1.0.apk` — „като играч“ (без DBG; има „Export Playtest Log“ в Настройки)

Можете да инсталирате и двата — не си пречат.

### Път 1 — само телефон (без компютър)
1. На телефона отворете браузър и влезте в GitHub → repo `CASEZERO` → branch `claude/case-zero-qa-spec-gh22bh` → папка `qa/apk`.
2. Натиснете `casezero-dev-0.1.0.apk` → **Download** (файлът е ≈ 29 MB).
3. Отворете изтегления файл. Android ще поиска **„Разреши инсталиране от този източник“** → разрешете за браузъра → върнете се → **Install**.
4. Ако се появи „Play Protect“ предупреждение → **Install anyway**. (Подписът е тестов; това е нормално.)
5. Повторете за `casezero-playtest-0.1.0.apk`.

### Път 2 — с компютър и `adb` (препоръчително: дава логове и save файлове)
1. На компютъра инсталирайте **Android platform-tools** (съдържа `adb`) от developer.android.com/tools/releases/platform-tools.
2. На телефона: **Settings → About phone → натиснете 7 пъти „Build number“** → появява се „Developer options“.
3. **Settings → Developer options → USB debugging = ON.**
4. Свържете кабела → на телефона потвърдете „Allow USB debugging“.
5. На компютъра, в папката на repo-то:
   ```sh
   git fetch origin claude/case-zero-qa-spec-gh22bh
   git checkout claude/case-zero-qa-spec-gh22bh
   adb devices                       # трябва да види устройството (state "device")
   sha256sum -c qa/apk/SHA256SUMS    # и двата трябва да са "OK"
   adb install -r qa/apk/casezero-dev-0.1.0.apk
   adb install -r qa/apk/casezero-playtest-0.1.0.apk
   ```
   (Windows: вместо `sha256sum` — `certutil -hashfile qa\apk\casezero-dev-0.1.0.apk SHA256` и сравнете с `qa/apk/SHA256SUMS`.)
6. Отворете втори терминал за лога и го оставете да работи през целия тест:
   ```sh
   adb logcat -s godot > test_log.txt
   ```

**Проверка след инсталацията:** на телефона има две иконки „CASE ZERO“ (dev и playtest). Запишете: инсталира се ли без грешка (**QA-INST: PASS/FAIL**).

**Чисто начало между тестовете** (изтрива save и analytics; по-късно ще ви трябва):
- с adb: `adb shell pm clear com.casezero.verticalslice.dev`
- без adb: Settings → Apps → CASE ZERO (dev) → Storage → **Clear storage**.

# ЧАСТ В — ПЪЛЕН ТЕСТ

## В.1 Решения на случаите (за да не блокирате)

Докосвайте обектите **по името им**; бутоните са на български.

**C01 „Отвореният прозорец“**
1. Tap **Отворен прозорец** → улика „Дъжд и отворен прозорец“. Затворете (×).
2. Tap **Под под прозореца** → улика „Сух под“. Затворете.
3. **Улики → Направи извод** → изберете *„Прозорецът вероятно е отворен наскоро; провери показанията.“* → **Потвърди** → **Към показанията**.
4. Tap **Карта: допълни показанията** → улика „Допълнени показания“. Затворете.
5. **Улики → Направи извод** → изберете *„Управителят го е отворил след намирането на госта, за да проветри.“* → **Потвърди** → SOLVED → **Продължи** → Reward **+100 XP** → **Следващ случай**.
Без улика (само текст): обувки, чаша, стенен часовник, покритото тяло.

**C02 „Последното обаждане“**
1. Tap **Телефон на госта** (0%) → улика „Батерия при намиране“. Затворете.
2. Tap **Зарядно и кабел** → бутон **Свържи** (става „Свързан“). Затворете.
3. Tap **телефона** отново → улика „Телефон и номер B“.
4. Tap **Проверена операторска справка**, после **Часовникът, посочен от Мира**.
5. **Улики → Направи извод** → изберете **Телефон и номер B**, **Пълна операторска справка**, **Час и статус на посочения запис** → **Свържи**.
6. Изберете *„Заявеният клетъчен разговор A → B в 23:30 не се е състоял.“* → **Потвърди**.

**C03 „Грешният влак“**
1. Tap петте: **билет, проверка на часовника, разписание, кадър, перон 4**.
2. **Улики → Направи извод** → подредете (от най-ранно): **R214 заминава 20:10:00** → **Начало на заявения интервал 20:15:00** → **Никола на перона 20:15:30** → **Потвърди**. (Докоснете карта, после докоснете слот.)
3. Свързване: **Проверено време**, **Никола на перона**, **Другият влак** → **Свържи**.
4. Изберете *„Никола не е бил в R214 през цялата минута 20:15; вижда се на перон 4.“* → **Потвърди** → … → край „Три случая. Една нова следа: АРХИВ 0.“; XP = 300.

## 3. Какво да събирате при проблем (за ВСЕКИ FAIL)

1. **Скрийншот** (бутони захранване + намаляване на звука).
2. Модел, Android версия, кой APK (dev/playtest), стъпките (1., 2., 3.), очаквано, получено.
3. Колко пъти се повтаря (напр. 3 от 3).
4. Ако имате adb:
   ```sh
   adb logcat -d -s godot > bug_QAxx.log
   adb exec-out run-as com.casezero.verticalslice.dev cat files/save/save.json > save.json
   adb exec-out run-as com.casezero.verticalslice.dev cat files/analytics/events.jsonl > events.jsonl
   ```
   (`run-as` работи само с **dev** APK.)
5. По възможност **видео на екрана** (Screen recorder) за QA11, QA19, QA13.
